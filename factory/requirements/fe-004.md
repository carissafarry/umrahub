# [fe-004] i18n

## Ringkasan
Umra Hub harus bisa dipakai dalam Bahasa Indonesia (bawaan) dan English. Pengguna bisa mengganti bahasa dari tombol di header yang ada di **setiap halaman**, dan pilihannya diingat di kunjungan berikutnya. Karena Umra Hub direncanakan menjadi platform besar, i18n dibangun di atas library **`next-intl`** sejak awal, dan semua teks UI yang sudah ada dipindah ke file pesan supaya fitur berikutnya tinggal menambah kunci terjemahan.

## User story
- Sebagai calon jamaah yang tinggal di luar negeri, saya ingin mengganti bahasa ke English dari halaman mana pun, supaya saya paham setiap langkah persiapan tanpa salah tafsir.
- Sebagai pengguna di Indonesia, saya ingin langsung melihat Bahasa Indonesia tanpa harus memilih apa pun.
- Sebagai developer fitur berikutnya, saya ingin satu cara baku (next-intl) untuk menulis teks UI dan header bersama yang sudah ada, supaya semua halaman baru otomatis dua bahasa dan punya tombol bahasa.

## Alur pengguna
1. Pengunjung baru membuka `/` → halaman tampil dalam Bahasa Indonesia, `<html lang="id">`.
2. Pengunjung menekan tombol bahasa di header (`ID` / `EN`) → halaman yang sama langsung tampil dalam English, `<html lang="en">`, tanpa pindah URL.
3. Pengunjung menutup tab lalu kembali → bahasa terakhir (English) masih aktif karena tersimpan di cookie.
4. Pengunjung membuka halaman lain (halaman yang ditambahkan task berikutnya) → header dan tombol bahasa yang sama tetap ada, bahasa tetap English.
5. Pengunjung menekan tombol lagi → kembali ke Bahasa Indonesia.
6. Jalur gagal: cookie berisi nilai tidak dikenal (mis. `fr`) atau rusak → aplikasi memakai Bahasa Indonesia dan tidak error.

## Kebutuhan fungsional
1. Pakai library **`next-intl`** (versi stabil terbaru yang mendukung Next.js 15 App Router), dalam mode **tanpa routing per-locale**: locale dibaca dari cookie di `i18n/request.ts` (`getRequestConfig`), bukan dari segmen URL.
2. Dua locale: `id` (bawaan) dan `en`. Tidak ada locale lain.
3. Locale ditentukan dari cookie `NEXT_LOCALE`; tanpa cookie atau nilai tidak valid → `id`. Header `Accept-Language` **tidak** dipakai (bawaan selalu Indonesia).
4. Cookie disimpan 1 tahun, `path=/`, `SameSite=Lax`.
5. URL tidak berubah per bahasa (tidak ada `/en/...`).
6. **Header bersama `SiteHeader`** dipasang di `src/app/layout.tsx`, sehingga muncul di setiap halaman: wordmark "Umra Hub" (link ke `/`) di kiri, `LanguageToggle` di kanan. Header yang sekarang ada di dalam `page.tsx` dipindah ke komponen ini, bukan diduplikasi.
7. Semua teks yang terlihat di landing page (judul, deskripsi, tombol, catatan, kartu manfaat, footer, `aria-label`, `alt`) dan metadata halaman (`title`, `description` via `generateMetadata`) berasal dari `messages/id.json` dan `messages/en.json`, dipanggil lewat `next-intl` (`getTranslations` di Server Component, `useTranslations` di Client Component).
8. Kedua file pesan punya kunci yang persis sama; test Vitest gagal kalau ada kunci yang hilang di salah satunya.
9. `<html lang>` mengikuti locale aktif.
10. **Ejaan ibadah:** selalu **"Umrah"** di kedua bahasa (keputusan pengguna 2026-10-18, menggantikan keputusan "Umroh" sebelumnya). Tidak boleh ada "Umroh" di teks mana pun. Nama brand ditulis **"Umra Hub"**.
10a. **Ganti nama brand:** platform sekarang bernama **"Umra Hub"** (dengan spasi) — domain `umrohhub` sudah dipakai orang. Semua "UmrohHub" yang terlihat di web (wordmark, `title`, `description`, footer, teks hero, alt/aria) diganti "Umra Hub" di kedua bahasa. Nama brand tidak diterjemahkan.
11. Teks Arab (talbiyah) tidak diterjemahkan dan tetap `lang="ar" dir="rtl"`.
12. Istilah ibadah yang umum tetap dalam bentuk aslinya di kedua bahasa: *umroh/Umrah, ihram, tawaf, sa'i, tahallul, manasik, doa, miqat*. Istilah yang kurang umum: terjemahan + istilah asli dalam kurung saat pertama muncul.
13. Tahun di footer dihitung saat render (tidak lagi tertulis "2026").

## Kasus tepi
- Cookie tidak valid atau kosong → `id`, tanpa error di console.
- JavaScript lambat/mati → halaman tetap tampil benar dalam bahasa dari cookie (render di server).
- Kunci terjemahan hilang saat runtime → tampilkan teks Indonesia sebagai cadangan (`onError`/`getMessageFallback` next-intl), bukan nama kunci mentah.
- Layar 360px: tombol bahasa tetap ≥ 44px dan header tidak mendorong konten keluar layar.
- Desktop ≥ 1024px: header mengikuti lebar container desktop (max ~1200px), sesuai aturan responsif di AGENTS.md.
- Teks English biasanya lebih panjang: judul hero dan tombol tidak boleh terpotong atau keluar kartu di 390, 768 dan 1280px.

## Data & backend
- Tidak ada perubahan database. (`users.preferred_language` di spec produk dipakai setelah login ada — di luar cakupan task ini.)
- Penggantian bahasa memakai **Server Action** kecil yang menulis cookie `NEXT_LOCALE` lalu `revalidatePath('/', 'layout')` / `router.refresh()`. Tidak ada endpoint publik baru.
- **Dependency baru:** `next-intl`. Sudah disetujui pengguna (2026-10-18: "pake library aja"); approver tetap akan menandainya, cukup konfirmasi.

## UI & copy
- `SiteHeader`: wordmark kiri, `LanguageToggle` kanan. `LanguageToggle` memakai `SegmentedControl` dari `src/components/ui` (pil kecil `ID | EN`), **bukan** indigo penuh — indigo tetap hanya untuk CTA utama.
- `aria-label` tombol: "Ganti bahasa" / "Change language".
- Copy English mengikuti nada yang sama: tenang, ramah, untuk pemula. Contoh: "Persiapan Umrah mandiri, lebih tenang dan terarah" → "Prepare for your independent Umrah, calmly and step by step".
- Tidak ada perubahan visual lain di luar header (dan nama brand "Umra Hub").

- Navigasi utama (top nav desktop / BottomNav mobile) — hanya wordmark + tombol bahasa di header untuk sekarang.
