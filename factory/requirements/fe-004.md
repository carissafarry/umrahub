# [fe-004] i18n

## Ringkasan
UmrohHub harus bisa dipakai dalam Bahasa Indonesia (bawaan) dan English. Diaspora Indonesia dan keluarga yang lebih nyaman berbahasa Inggris bisa mengganti bahasa lewat tombol di header, dan pilihannya diingat di kunjungan berikutnya. Semua teks UI yang sudah ada dipindah ke file pesan, supaya fitur berikutnya tinggal menambah kunci terjemahan.

## User story
- Sebagai calon jamaah yang tinggal di luar negeri, saya ingin mengganti bahasa ke English, supaya saya paham setiap langkah persiapan tanpa salah tafsir.
- Sebagai pengguna di Indonesia, saya ingin langsung melihat Bahasa Indonesia tanpa harus memilih apa pun.
- Sebagai developer fitur berikutnya, saya ingin satu cara baku untuk menulis teks UI, supaya semua halaman konsisten dua bahasa.

## Alur pengguna
1. Pengunjung baru membuka `/` → halaman tampil dalam Bahasa Indonesia, `<html lang="id">`.
2. Pengunjung menekan tombol bahasa di header (label `ID` / `EN`) → halaman yang sama langsung tampil dalam English, `<html lang="en">`, tanpa pindah URL dan tanpa reload penuh yang terasa.
3. Pengunjung menutup tab lalu kembali → bahasa terakhir (English) masih aktif karena tersimpan di cookie.
4. Pengunjung menekan tombol lagi → kembali ke Bahasa Indonesia.
5. Jalur gagal: cookie berisi nilai tidak dikenal (mis. `fr`) atau rusak → aplikasi memakai Bahasa Indonesia dan tidak error.

## Kebutuhan fungsional
1. Dua locale: `id` (bawaan) dan `en`. Tidak ada locale lain.
2. Locale ditentukan dari cookie `NEXT_LOCALE`; tanpa cookie atau nilai tidak valid → `id`. Header `Accept-Language` **tidak** dipakai (bawaan selalu Indonesia).
3. Cookie disimpan 1 tahun, `path=/`, `SameSite=Lax`.
4. URL tidak berubah per bahasa (tidak ada `/en/...`).
5. Semua teks yang terlihat di landing page (judul, deskripsi, tombol, catatan, kartu manfaat, footer, `aria-label`, `alt`) dan metadata halaman (`title`, `description`) berasal dari file pesan `messages/id.json` dan `messages/en.json`.
6. Kedua file pesan punya kunci yang persis sama; test gagal kalau ada kunci yang hilang di salah satunya.
7. `<html lang>` mengikuti locale aktif.
8. Tombol bahasa adalah komponen `LanguageToggle` yang bisa dipakai ulang di header halaman lain nanti.
9. Teks Arab (talbiyah) tidak diterjemahkan dan tetap `lang="ar" dir="rtl"`; terjemahan/transliterasinya boleh ikut locale.
10. Istilah ibadah yang sudah umum tetap dalam bentuk Arab-Latin di kedua bahasa: *umrah/umroh, ihram, tawaf, sa'i, tahallul, manasik, doa, miqat*. Istilah yang kurang umum ditulis dengan terjemahan + istilah aslinya dalam kurung saat pertama muncul.

## Kasus tepi
- Cookie tidak valid atau kosong → `id`, tanpa error di console.
- JavaScript lambat/mati → halaman tetap tampil benar dalam bahasa dari cookie (render di server).
- Kunci terjemahan hilang saat runtime → tampilkan teks Indonesia sebagai cadangan, bukan nama kunci mentah. (Test di poin 6 mencegah ini lolos.)
- Layar 360px: tombol bahasa tetap ≥ 44px dan tidak mendorong konten keluar layar.
- Teks English biasanya lebih panjang: judul hero dan tombol tidak boleh terpotong atau keluar kartu.

## Data & backend
- Tidak ada perubahan database. (`users.preferred_language` di spec produk baru dipakai setelah login ada — di luar cakupan task ini.)
- Tidak ada endpoint baru. Penggantian bahasa memakai Server Action atau route handler kecil yang hanya menulis cookie lalu me-refresh halaman.

## UI & copy
- Header landing page: wordmark "UmrohHub" di kiri, `LanguageToggle` di kanan — bentuk pil/segmented kecil dari `src/components/ui` (`SegmentedControl` atau `Chip`), bukan warna indigo penuh (indigo tetap hanya untuk CTA utama).
- Label tombol: `ID` dan `EN`, dengan `aria-label` "Ganti bahasa" / "Change language".
- Copy English mengikuti nada yang sama: tenang, ramah, untuk pemula. Contoh: "Persiapan Umrah mandiri, lebih tenang dan terarah" → "Prepare for your independent Umrah, calmly and step by step".
- Tidak ada perubahan visual lain di luar header.

## Kriteria selesai
- [ ] Tanpa cookie, `/` tampil dalam Bahasa Indonesia dan `<html lang="id">`.
- [ ] Klik `EN` → semua teks landing page dan `document.title` jadi English, `<html lang="en">`.
- [ ] Reload setelah memilih `EN` → tetap English.
- [ ] Cookie `NEXT_LOCALE=fr` → Bahasa Indonesia, tanpa error.
- [ ] `grep` di `src/app/page.tsx` tidak menemukan teks UI Indonesia/English yang ditulis langsung (kecuali teks Arab dan nama brand).
- [ ] Test memastikan `messages/id.json` dan `messages/en.json` punya kunci yang sama.
- [ ] Tombol bahasa ≥ 44×44px, bisa difokus dengan keyboard, dan tidak membuat scroll horizontal di 360px.
- [ ] `AGENTS.md` menjelaskan cara menambah teks baru (kunci di kedua file pesan, cara memanggilnya di Server/Client Component).
- [ ] Lint, typecheck, test, dan `build:check` lolos.

## Di luar cakupan
- Menyimpan bahasa ke profil pengguna di database (`users.preferred_language`) — menunggu be-006 (Google auth).
- Locale ketiga (Arab, Melayu, dll.).
- Menerjemahkan konten langkah persiapan dari database — sudah dua bahasa di tabel (`title_id`/`title_en`), dipakai oleh task checklist.
- URL per bahasa dan SEO hreflang.

## Pertanyaan terbuka
1. **Library atau buatan sendiri?** `next-intl` paling umum untuk App Router, tapi menambah dependency — approver akan otomatis eskalasi ke kamu. Alternatifnya helper kecil buatan sendiri (kamus JSON + fungsi `t()`), cukup untuk 2 bahasa tanpa URL per locale. Pilih salah satu.
2. Apakah tombol bahasa juga perlu ada di halaman lain setelah login (header aplikasi), atau cukup di landing dulu? Requirement ini mengasumsikan komponennya dibuat reusable tapi hanya dipasang di landing.
3. Untuk "Umrah" vs "Umroh": Bahasa Indonesia di landing saat ini memakai "Umrah". Mau diseragamkan "Umrah" atau "Umroh" (sesuai nama brand UmrohHub)?
